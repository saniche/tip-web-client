# Implementation Plan: Interest Management UI

**Branch**: `004-interest-management` | **Date**: 2026-10-22 | **Spec**: [specs/004-interest-management/spec.md](spec.md)

**Input**: Feature specification from `specs/004-interest-management/spec.md`

## Summary

Implement the frontend experience for managing user job interests in the Talent Intelligence Platform. Users can browse their saved interests at `/jobs/interests`, search and filter with 300 ms debounced inputs, navigate paginated results, remove interests with confirmation prompts, and toggle job interest directly from the normalized job details view (`/normalized-jobs/:id`).

## Technical Context

**Language/Version**: TypeScript ~6.0.2, HTML, SCSS
**Primary Dependencies**: Angular 22.1 (`@angular/core`, `@angular/common`, `@angular/router`, `@angular/forms`), RxJS ~7.8.0, Bootstrap 5.3.8
**Storage**: Client Application State, Browser URL Query Parameters
**Testing**: Vitest 4.0.8, Angular Component / Unit Testing (`npm test`)
**Target Platform**: Modern Web Browsers
**Project Type**: Single Page Web Application (Angular standalone components)
**Performance Goals**: List loads within 2 seconds; search debounces at 300 ms; removal updates UI in under 1 second post-server confirmation
**Constraints**: Server-side pagination; preserve backend creation-date descending order; prevent stale race conditions via RxJS `switchMap`
**Scale/Scope**: 1 new page component (`Interests`), 1 new navigation item, extension of `TipApi`, extension of `NormalizedJobDetail`

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- Library / Component Modular Design: Component separation respected; API service calls encapsulated in `TipApi`.
- Observability & Error Handling: Graceful loading, empty, and retry states implemented for all async operations.
- Test-First / Testability: Unit and integration tests for service calls, debounced filtering, and view state transitions.
